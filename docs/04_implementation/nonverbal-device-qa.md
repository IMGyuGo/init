# 모의면접 비언어 감지 실기기 QA

## 목적

Chrome, Safari, 저사양 Windows 환경에서 시선·고개 감지의 오탐/미탐과 카메라 프레임 저하를 같은 기준으로 확인한다.
이 QA 결과는 면접 평가 점수와 답변 메타데이터에 저장하지 않으며, 브라우저에서 내려받은 진단 JSON으로만 비교한다.

## QA 모드 실행

1. 로컬 서버를 실행한다.
2. 모의면접 런타임 URL에 `nonverbalQa=1`을 추가한다.
   - 예: `/candidate/mock-interviews/1?nonverbalQa=1`
3. 장치 점검을 완료하고 답변 녹화를 시작한다.
4. 좌측 하단 `실기기 QA` 패널에서 성능 지표와 시나리오 결과를 확인한다.
5. 문항 테스트가 끝나면 `JSON 저장`을 눌러 결과를 보관한다.

QA 패널은 모의면접에서만 활성화된다. 일반 URL과 채용면접에서는 표시되지 않는다.

## 시나리오

각 시나리오는 최소 3초 이상 측정한다. 이탈 시나리오는 3~5초 동안 동작한 뒤 정면으로 돌아오고 약 1초 후 구간을 종료한다.

| 시나리오 | 수행 방법 | 기대 결과 |
| --- | --- | --- |
| 정면 유지 | 얼굴과 눈을 자연스럽게 정면에 두고 5초 이상 유지 | `GAZE_AWAY`가 없어 `PASS` |
| 눈동자 이탈 | 고개는 정면에 두고 눈동자만 좌/우 또는 아래로 이동한 뒤 복귀 | `IRIS` 또는 `COMBINED` 신호로 `PASS` |
| 고개 회전 | 눈은 자연스럽게 두고 고개를 좌/우로 돌린 뒤 복귀 | `HEAD_POSE` 또는 `COMBINED` 신호로 `PASS` |

`INCOMPLETE`는 측정 시간이 3초 미만인 경우다. `FAIL`은 정면 유지 중 오탐이 발생했거나 의도한 이탈 신호가 감지되지 않은 경우다.

## 성능 판정

측정 시작 후 5초 동안은 `측정 중`으로 표시한다.

| 상태 | 기준 |
| --- | --- |
| 원활 | 감지 완료율 85% 이상, 처리시간 p95 350ms 이하, 감지 오류 없음, 영상 FPS 정상 |
| 성능 저하 | 감지 완료율 65% 이상, 처리시간 p95 600ms 이하, 영상 FPS 사용 가능 수준 |
| 점검 필요 | 위 기준 미달 |
| 분석 불가 | 브라우저에서 감지 API/모델을 사용할 수 없고 완료 표본이 없음 |

영상 FPS의 정상 기준은 카메라 명목 FPS의 75% 또는 20fps 중 더 낮은 값이다. 사용 가능 기준은 명목 FPS의 50% 또는 12fps 중 더 낮은 값이다.
브라우저가 `requestVideoFrameCallback`을 지원하지 않으면 영상 FPS는 `측정 미지원`으로 표시하고, 감지 완료율과 처리시간으로 성능을 판정한다.

## 기기 매트릭스

| 환경 | 필수 확인 |
| --- | --- |
| Windows Chrome | 정면/눈동자/고개 시나리오 각 2회, 720p 카메라 기준 성능 상태 |
| macOS Chrome | 위 시나리오와 WebM 녹화 병행 시 성능 상태 |
| macOS Safari | 위 시나리오와 MP4/M4A fallback 녹화 병행 시 성능 상태 |
| 저사양 Windows Chrome | CPU 4스레드 이하 또는 개발자 도구 CPU 4x slowdown에서 완료율, p95, 영상 FPS |

각 환경에서 다음 조건을 만족해야 통과로 본다.

- 정면 유지 2회 모두 `PASS`
- 눈동자 이탈과 고개 회전이 각각 2회 중 1회 이상 `PASS`
- `점검 필요`가 지속되지 않음
- 녹화·질문 타이머·답변 제출 조작에 눈에 띄는 지연이 없음
- 저장한 JSON에 브라우저, 카메라 설정, 감지 완료율, 처리시간, 영상 FPS, 시나리오 결과가 포함됨

## 결과 공유

파일명은 `nonverbal-device-qa-{timestamp}.json`이다. PR 또는 QA 댓글에는 아래 내용을 함께 남긴다.

- OS와 버전
- 브라우저와 버전
- CPU/메모리 또는 기기 모델
- 카메라 해상도와 명목 FPS
- 패널 성능 상태
- 시나리오별 PASS/FAIL
- 오탐 또는 프레임 저하가 발생한 재현 동작
