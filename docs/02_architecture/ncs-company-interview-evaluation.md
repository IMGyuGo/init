# 공식 NCS·기업 인재상 기반 채용면접 평가 프로필

## 목적

채용면접 평가는 하나의 범용 점수가 아니라 다음 세 출처를 분리해 구성한다.

| 출처 | 기본 비중 | 역할 |
| --- | ---: | --- |
| 한국산업인력공단 공식 NCS 능력단위 | 60 | 해당 직무에서 수행해야 할 능력과 능력단위요소를 평가 |
| 기업 인재상·평가 정책 | 25 | 기업이 명시한 가치 중 직무와 연결된 관찰 가능한 행동을 평가 |
| 서비스 공통 근거 기반 rubric | 15 | 답변이 상황, 본인 행동, 선택 근거, 결과, 학습을 제시하는지 평가 |

NCS 원천은 공공데이터포털 `국가직무능력표준(NCS) 기준정보 조회 서비스`의 `NCS007` 능력단위 검색 API다. 저장 시 공식 분류 코드, 능력단위 코드, NCS 차수, 버전, 능력단위요소와 원문 스냅샷을 함께 보존한다.

## 설정 흐름

1. 기업은 공고 JD와 회사 프로필의 인재상·평가 정책을 작성한다.
2. API가 공식 NCS 능력단위를 검색·캐시하고 JD 관련 후보를 제시한다.
3. 기업 담당자가 공식 능력단위 3~5개와 내부 비중을 최종 선택한다.
4. 시스템이 NCS 기준, 기업 직무행동 기준, 공통 답변 근거 기준을 `evaluation_criteria`로 물질화한다.
5. 각 평가 기준에 독립 질문을 최소 2개 연결한다.
6. 커버리지 검증을 통과하면 프로필을 `ACTIVE`로 전환한다.
7. 채용면접 완료 시 활성 프로필 스냅샷과 답변 근거를 worker에 전달한다.

## 5단계 근거 rubric

| 단계 | 기준 점수 | 답변 근거 수준 |
| --- | ---: | --- |
| 5 | 100 | 구체적 경험, 선택 근거, 결과, 개선까지 제시 |
| 4 | 85 | 구체적 경험, 본인 행동, 결과를 제시 |
| 3 | 70 | 관련 경험은 있으나 본인 행동 또는 결과가 일부 부족 |
| 2 | 50 | 개념 설명은 있으나 실제 경험 근거가 부족 |
| 1 | 25 | 질문과 관련은 있으나 해당 능력을 뒷받침하지 못함 |

STT가 없으면 답변 품질을 추론하지 않고 해당 답변을 임시 0점·낮은 신뢰도로 표시한다. 짧거나 모호한 답변, 본인 행동·결과가 없는 답변, 부실한 꼬리질문 답변은 근거 부족으로 보수적으로 평가한다.

## 기업 인재상 적용 원칙

- `도전`, `협업`, `고객 중심` 같은 추상어를 그대로 점수화하지 않는다.
- JD와 연결된 과거 행동, 선택, 조율 방식, 결과처럼 면접 답변에서 관찰 가능한 문장으로 변환한다.
- 출신학교, 성별, 나이, 지역, 장애·건강, 외모, 음성 특성 등 민감하거나 직무 무관한 특성은 평가하지 않는다.
- 기업 인재상은 공고별 스냅샷으로 보존해 이후 회사 프로필이 바뀌어도 당시 평가 계약을 재현할 수 있게 한다.

## 채용 의사결정 경계

- AI는 기준별 점수, 근거 답변, 불확실성을 제공한다.
- 자동 합격·탈락 또는 최종 채용 결정을 생성하지 않는다.
- 비언어 및 응시 무결성 신호는 별도 검토 참고 정보이며 NCS·인재상 점수에 포함하지 않는다.
- 기업 담당자는 공식 코드·버전, 질문 커버리지, 근거 답변을 확인한 뒤 사람의 판단으로 검토한다.

## 운영 설정

```env
NCS_PUBLIC_DATA_SERVICE_KEY=
NCS_PUBLIC_DATA_BASE_URL=https://apis.data.go.kr/B490007/hrdkapi
NCS_PUBLIC_DATA_SEARCH_LEVEL=1
NCS_PUBLIC_DATA_TIMEOUT_MS=10000
NCS_CATALOG_SOURCE_UPDATED_AT=2025-06-09
```

서비스 키가 없으면 이미 동기화된 로컬 카탈로그만 조회하며, 공식 데이터가 없는 경우 임의 기준을 공식 NCS처럼 생성하지 않는다.
