# Realtime RMS 립싱크 비교 설계

## 배경

`/interviewer-preview`에는 OpenAI Realtime 음성으로 립싱크를 조정하는 튜닝 패널이 있다. 기존 비교 구현은 이 패널과 별개로 합성 WAV를 재생하는 `RMS 오디오 입력` 영역을 추가했지만, 이는 사용자가 원하는 비교 기준과 다르다.

비교 대상은 다음 두 방식이다.

- 현재 방식: 테스트 문장의 문자 진행과 RMS를 함께 사용하는 Viseme + RMS 립싱크
- 수정 전 방식: 오디오 RMS 임계값만으로 `rest`, `closed`, `open`을 선택하는 립싱크

두 방식은 같은 문장만 사용하는 수준이 아니라, 한 번 생성된 동일한 OpenAI Realtime 음성과 동일한 RMS 분석값을 동시에 사용해야 한다.

## 목표

- OpenAI Realtime 립싱크 튜닝 패널 안에서 두 방식을 동시에 비교한다.
- Realtime 음성 요청, 테스트 문장, 재생 상태, 오디오 스트림을 한 번만 생성하고 공유한다.
- 데스크톱에서는 현재 방식 오른쪽에 수정 전 RMS 전용 방식을 배치한다.
- 좁은 화면에서는 현재 방식 아래에 RMS 전용 방식을 배치한다.
- 기존 면접 화면의 기본 PNG 렌더링과 저장된 튜닝 설정 동작은 변경하지 않는다.

## 비목표

- 실제 면접 화면에 렌더러 선택 기능을 추가하지 않는다.
- OpenAI Realtime 세션이나 음성 요청을 비교 방식별로 두 번 생성하지 않는다.
- 수정 전 RMS 방식을 운영 기본값으로 되돌리지 않는다.
- 새로운 아바타 이미지나 입 모양 에셋을 만들지 않는다.

## 화면 구성

기존 튜닝 패널의 왼쪽 제어 영역은 유지한다.

- 테스트 문장 입력
- Realtime 음성 테스트 시작 및 중지
- 튜닝 슬라이더
- 설정 저장 및 기본값 초기화
- 상태 메시지

오른쪽 미리보기 영역은 두 개의 비교 카드로 바꾼다.

1. `현재 · Viseme + RMS`
   - 현재 `useLipSyncDriverState`의 `mouthShape`, `mouthOpen`을 사용한다.
   - 현재 튜닝 슬라이더 값을 그대로 반영한다.
2. `수정 전 · RMS 전용`
   - 같은 드라이버가 계산한 `rms`를 `getMouthShapeForRms`에 전달한다.
   - 재생 중이 아니거나 모션 감소가 활성화되면 `rest`를 사용한다.
   - `rendererMode="legacy-rms"`로 수정 전 `talking.png` 자세와 `closed` 입 패치를 사용한다.

데스크톱에서는 두 카드를 같은 행에 배치하고, 모바일에서는 현재 방식 다음에 RMS 전용 방식을 세로로 배치한다. 각 카드 헤더에는 현재 입 모양 이름을 표시한다.

## 데이터 흐름

```text
테스트 문장
  -> RealtimeLipSyncTuningController.play()
  -> OpenAI Realtime 음성 1회 생성
  -> remoteAudioElement / remoteStream
  -> useLipSyncDriverState 1회 실행
       -> current mouthShape + mouthOpen -> 현재 카드
       -> rms -> getMouthShapeForRms -> RMS 전용 카드
```

두 번째 `useLipSyncDriverState`나 두 번째 AudioContext를 만들지 않는다. 이렇게 해야 오디오 프레임, 재생 시작 시점, 무음 구간이 완전히 같은 조건에서 비교된다.

## 입 모양 전환 기록

기존 `최근 입 모양 전환` 기록은 비교 기록으로 확장한다.

- 문자 위치는 현재 드라이버의 `sourceCharacterIndex`를 사용한다.
- 현재 카드 또는 RMS 전용 카드의 입 모양이 바뀔 때 한 행을 추가한다.
- 행에는 `문자`, `현재`, `RMS 전용` 값을 표시한다.
- 같은 조합이 연속으로 반복되면 기록하지 않는다.
- 최근 24개 기록 제한을 유지한다.

이 기록은 시각적으로 놓칠 수 있는 차이를 확인하는 QA 보조 수단이며, 립싱크 계산에는 관여하지 않는다.

## 기존 잘못된 비교 영역 정리

별도 `InterviewerAudioLipSyncQa`와 합성 WAV 생성 코드를 제거한다. 함께 제거하는 항목은 다음과 같다.

- `RMS 오디오 입력` 제어 영역
- `로컬 음원 재생` 버튼과 오디오 컨트롤
- 합성 톤 구간 및 WAV Blob 생성 함수
- 별도 오디오 QA 전용 스타일과 테스트

RMS 전용 입 모양을 계산하는 순수 함수는 Realtime 튜닝 비교에서 재사용할 수 있는 위치로 옮긴다.

## 상태 및 오류 처리

- `connecting`: 두 카드 모두 대기 자세를 유지한다.
- `playing`: 두 카드가 동일 스트림으로 동시에 말한다.
- `idle`, `error`, 중지, 재생 완료: 두 카드 모두 `rest`와 대기 자세로 돌아간다.
- Realtime 연결 오류 메시지는 기존 상태 영역 하나에서 표시한다.
- 테스트 문장 불일치로 재생이 중단되는 기존 검증 로직을 유지한다.
- 모션 감소 설정에서는 두 카드 모두 입 모양 애니메이션을 멈춘다.

## 테스트 전략

### 단위 테스트

- RMS 전용 계산이 무음, 중간 RMS, 높은 RMS에서 각각 `rest`, `closed`, `open`을 반환한다.
- 재생 중이 아니거나 모션 감소가 활성화되면 `rest`를 반환한다.
- 비교 패널에 현재 및 RMS 전용 카드가 모두 렌더링된다.
- RMS 전용 카드가 `legacy-rms` 렌더러 모드로 연결된다.
- 숨겨진 Realtime 오디오 요소와 재생 버튼은 각각 하나만 존재한다.
- 별도 로컬 RMS QA 영역이 더 이상 렌더링되지 않는다.

### 통합 및 수동 검증

- 한 테스트 문장을 한 번 재생했을 때 두 카드가 동시에 speaking 상태가 되는지 확인한다.
- 같은 재생 중 현재 방식은 다양한 Viseme을, RMS 전용 방식은 `rest`, `closed`, `open`만 사용하는지 확인한다.
- 재생 종료 후 두 카드가 모두 idle/rest로 돌아오는지 확인한다.
- 데스크톱에서는 좌우, 좁은 화면에서는 상하 배치가 되는지 확인한다.
- 후보자 아바타 테스트, TypeScript 검사, 프로덕션 빌드, Role D 로컬 하네스를 실행한다.

## 완료 조건

- OpenAI Realtime 립싱크 튜닝에서 한 번의 재생으로 두 방식이 동시에 움직인다.
- 두 방식이 동일한 Realtime 스트림과 RMS 분석값을 공유한다.
- 별도 합성 WAV 기반 RMS 비교 영역이 제거된다.
- 실제 면접 화면의 기본 동작에는 변화가 없다.
